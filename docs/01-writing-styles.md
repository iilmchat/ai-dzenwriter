# Стили написания и политика фактов

**Статус:** v1, конфигурация в репозитории  
**Дата:** 22.10.2026  
**Связанные документы:** [00-design](00-design.md), [ADR-0003](adr/0003-styles-as-config.md), [ADR-0004](adr/0004-structured-output-and-fact-gates.md)

Стиль задаёт голос, аудиторию, политику фактов, набор проверок и инструкции для модели. Формат задаёт каркас и объём (`config/formats.yaml`). При генерации используются оба слоя.

Файлы:

- [`config/styles/industry-news.yaml`](../config/styles/industry-news.yaml)
- [`config/styles/company-achievements.yaml`](../config/styles/company-achievements.yaml)
- [`config/styles/product-description.yaml`](../config/styles/product-description.yaml)
- [`config/styles/personal-experience.yaml`](../config/styles/personal-experience.yaml)
- [`config/formats.yaml`](../config/formats.yaml)

## 1. Политика фактов

| Режим             | Что разрешено                                                     | Что запрещено                                                                        | Какие факты нужны                                                                         |
| ----------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| `sourced`         | Утверждения со ссылкой на источник; оценки, помеченные как оценка | Числа, имена и даты без источника                                                    | `news_source` с URL и датой публикации                                                    |
| `approved_only`   | Только одобренные факты компании или продукта                     | Неодобренные факты; превосходные степени без факта; названия клиентов без разрешения | `company_fact` или `product_fact` со статусом `approved`                                  |
| `experience_only` | События, числа и выводы из заметок опыта с согласием              | Выдуманные события, числа, сроки и имена; иллюстративные истории                     | `experience_note` со статусом `approved`, `consent_confirmed = true`, `anonymized = true` |

Общее правило для всех режимов: утверждение без `fact_ids` может быть только гипотезой или оценкой.

## 2. Стили

### 2.1. Новости индустрии (`industry-news`)

- **Для кого:** разработчики, продуктовые менеджеры, руководители.
- **Голос:** третье лицо, аналитический, технический. Оценки помечаются явно.
- **Форматы:** новость, статья, лонгрид.
- **Факты:** `sourced`. Минимум один источник с датой.
- **Характерные проверки:** числа и имена по фактам, дата источника, запрет гарантий.
- **Ориентир структуры (не факт):** что произошло → кто и когда → технические детали → что это меняет → что проверить.

### 2.2. Наш опыт и достижения (`company-achievements`)

- **Для кого:** клиенты, партнёры, инженеры и руководители, которые выбирают ИИ-решения.
- **Голос:** «мы», описательный, без самовосхваления.
- **Форматы:** кейс, статья, новость.
- **Факты:** `approved_only`. Минимум два одобренных факта компании.
- **Характерные проверки:** превосходные степени требуют факта; клиенты называются только при разрешении.
- **Структура достижения:** задача → что сделали → что изменилось → что проверили → что дальше.

### 2.3. Описание продукта (`product-description`)

- **Для кого:** потенциальные пользователи, которые ещё не знают продукт.
- **Голос:** «вы», дружелюбный и описательный, термины с пояснением.
- **Форматы:** статья, подборка, лонгрид.
- **Факты:** `approved_only`. Минимум три одобренных факта о продукте, среди них ограничения.
- **Характерные проверки:** маркировка рекламы обязательна до утверждения; обещания результата запрещены без факта.
- **Структура:** для кого → задача → как начать (три шага) → что умеет → чего не умеет → условия (только при одобренном факте).

### 2.4. Личный опыт пользователя ИИ-систем (`personal-experience`)

- **Для кого:** пользователи ИИ-систем, которым важны реальные истории.
- **Голос:** «я», разговорный, от пользователя, а не от компании.
- **Форматы:** кейс, лонгрид, статья.
- **Факты:** `experience_only`. Заметки от 800 знаков, согласие и обезличивание обязательны.
- **Характерные проверки:** первое лицо обязательно; имена людей заменены ролями; числа только из заметок; оговорка «личный опыт» в конце добавляется всегда.
- **Структура:** задача → что пробовал → что сработало и что нет → что изменил → вывод.
- **Если заметок мало:** модель возвращает `needs_input` с вопросами автору. История не дописывается.

## 3. Формат конфигурации стиля

| Поле                          | Тип                 | Назначение                                                                                                     |
| ----------------------------- | ------------------- | -------------------------------------------------------------------------------------------------------------- |
| `id`                          | строка              | Уникальный идентификатор, совпадает с именем файла                                                             |
| `version`                     | целое               | Версия стиля, сохраняется в каждой версии материала                                                            |
| `name`, `summary`, `audience` | строка              | Тексты карточек в интерфейсе                                                                                   |
| `allowed_formats`             | список              | Форматы, доступные для стиля                                                                                   |
| `voice`                       | объект              | `person` (`first`, `we`, `third`), `register`, `default_tone`, `reader_address` (`you`, `none`)                |
| `inputs`                      | объект              | Обязательные типы фактов, минимум, дополнительные требования (согласие, обезличивание, длина заметок, продукт) |
| `fact_policy`                 | строка              | `sourced`, `approved_only` или `experience_only`                                                               |
| `checks`                      | объект              | Проверка и её уровень: `block` или `warn`. Нет ключа — проверка выключена                                      |
| `disclaimer`                  | объект              | Темы, для которых нужен дисклеймер; `always: true` — дисклеймер всегда                                         |
| `instructions`                | многострочный текст | Инструкции для модели, подставляются в блок «Стиль» промпта                                                    |

Правила валидации (проверяются при старте API и командой `pnpm config:validate`; при ошибке сервис не запускается). Реализованы в E1. Проверка роста `version` — процессная, выполняется в PR:

- `id` уникален и совпадает с именем файла;
- все `allowed_formats` существуют в `formats.yaml`;
- все ключи `checks` существуют в коде движка проверок;
- `fact_policy` — одно из трёх значений;
- `version` увеличивается при любом изменении инструкций или проверок.

## 4. Как менять стиль

1. Создать ветку и отредактировать YAML или промпт.
2. Увеличить `version`, если изменились инструкции или проверки.
3. Прогнать golden set (см. [00-design](00-design.md), раздел 7.4) и приложить результаты к PR.
4. Ревью руководителя контента, слияние в `main`.
5. После выкладки новые материалы используют новую версию. Уже созданные версии не меняются.

## 5. Словарь проверок

| Проверка                       | Значение                                                  |
| ------------------------------ | --------------------------------------------------------- |
| `numbers_must_map_to_facts`    | Каждое число в тексте есть в указанных фактах             |
| `names_must_map_to_facts`      | Каждое имя собственное есть в фактах или в теме           |
| `claims_need_fact_ids`         | Утверждения типа `fact` указывают существующие `fact_ids` |
| `superlatives_need_fact`       | Превосходные степени требуют факта                        |
| `guarantees_forbidden`         | Обещания результата запрещены                             |
| `source_date_required`         | У каждого источника есть дата публикации                  |
| `first_person_expected`        | В тексте есть первое лицо                                 |
| `personal_names_forbidden`     | Имена людей и компаний заменены ролями                    |
| `client_names_need_permission` | Клиенты названы только при разрешении                     |
| `ad_disclosure_required`       | У рекламного текста есть маркировка                       |
| `limitations_section_required` | В тексте о продукте есть раздел об ограничениях           |

Общие проверки для всех стилей — заголовок, SEO-заголовок, теги, объём, штампы, кликбейт, крючки, длина абзацев. Описаны в [00-design](00-design.md), раздел 7.3. Списки штампов, кликбейта, обещаний и превосходных степеней лежат в `config/checks.yaml`: правила меняются через PR вместе с промптом.
