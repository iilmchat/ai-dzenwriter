# ADR-0004. Структурированный вывод LLM и детерминированные гейты фактов

**Статус:** предложено  
**Дата:** 22.10.2026

## Контекст

Цифры, имена и личный опыт должны сверяться с фактами, а не с доверием к тексту модели. Текст статьи и метаданные должны разбираться надёжно. Исходный промпт просил формат `SEO_TITLE:` и подобные строки в конце. Разбор такого текста регулярными выражениями хрупок: любая правка формата ломает разбор.

## Решение

- Модель возвращает JSON по схеме: `status`, `title`, `article_markdown`, метаданные, `claims` с `fact_ids`, `questions`.
- Публичный текст собирается кодом в формат из спецификации Dzen Writer.
- Гейты: числа и имена сверяются с фактами кодом; утверждения без `fact_ids` помечаются; блокирующие проверки запрещают переход в `in_review`.
- Один повтор при ошибке схемы. Ответ без валидного JSON получает статус `failed`.
- В v1 приложение не загружает страницы по ссылкам и не выполняет инструкции из фактов. Факты — это данные.

## Альтернативы

- **Текст с метаданными в конце и разбор регулярными выражениями.** Просто, но хрупко. Отклонено.
- **Вторая LLM-проверка фактов.** Полезна как вспомогательный сигнал, но не как гейт: она тоже ошибается. Может появиться в v2 как предупреждение.
- **Загрузка страниц по URL для извлечения фактов.** Даёт больше данных, но открывает SSRF и prompt injection через веб-страницы. Отклонено для v1.

## Последствия

- Нужна поддержка structured output у провайдера или режим JSON с валидацией. Адаптер `LlmProvider` это скрывает.
- Эвристика имён даёт ложные срабатывания. Для подстройки есть кнопка «ложное срабатывание» и журнал.
- Качество проверяем golden set, а не на глаз.
