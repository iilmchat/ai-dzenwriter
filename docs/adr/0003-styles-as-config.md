# ADR-0003. Стили и форматы — конфигурация в git

**Статус:** предложено  
**Дата:** 22.10.2026

## Контекст

Стиль задаёт голос, политику фактов и проверки. Ошибка в стиле напрямую ведёт к выдуманным фактам, например к личному опыту с цифрами, которого не было. Такие правила нужно менять с ревью и историей изменений.

## Решение

- Стили и форматы — YAML-файлы в `config/`. Базовый промпт — `prompts/dzen_writer.md`.
- Изменения вносятся через PR с ревью руководителя контента. CODEOWNERS закрепит это после создания команды в организации.
- У каждого стиля есть поле `version`. Каждая версия материала хранит `style_version` и `prompt_version`.
- Валидация при старте API: некорректная конфигурация не даёт запуститься сервису.
- Редактирование стилей в интерфейсе — в v2. Тогда появятся версии в БД и тот же аудит.

## Альтернативы

- **Стили в базе данных с редактированием в интерфейсе.** Удобно, но правила меняются без ревью и без истории в git. Отклонено для v1.
- **Стили в коде (объекты TypeScript).** Работает, но редакторы не могут читать и предлагать правки. Отклонено.
- **Один общий промпт без стилей.** Не решает проблему фактов: у разных материалов разные голос и политика. Отклонено.

## Последствия

- Редакторы предлагают правки через PR и видят историю.
- Нужен golden set, чтобы оценивать влияние изменения (00-design, раздел 7.4).
- Формат YAML требует дисциплины: поля фиксированы схемой, лишние ключи — ошибка валидации.
