# ADR-0005. Доступ через GitHub OAuth, только для организации iilmchat

**Статус:** предложено  
**Дата:** 22.10.2026  
**Реализация:** E2, см. [04-implementation-status](../04-implementation-status.md). Вход, сессии и роли работают. Перепроверка членства раз в сутки пока не сделана: нужен серверный токен организации или GitHub App, решение открыто.

## Контекст

Инструмент внутренний. Пользователи уже состоят в GitHub-организации `iilmchat`. Заводить отдельные пароли или вход по почте не хочется. Вход по magic link работает в ai-ticketbuyer, но он рассчитан на пользователей-потребителей и не связан с членством в организации.

## Решение

- Вход через GitHub OAuth App с минимальными scope: `read:user` и `read:org`.
- Доступ открыт только участникам организации `iilmchat`. Проверка выполняется при каждом входе.
- Роли и отключение пользователей хранятся в БД приложения. Первый администратор задаётся переменной окружения `ADMIN_GITHUB_LOGINS`.
- Сессии — непрозрачные токены в БД, cookie HttpOnly. Так же, как в ai-ticketbuyer.
- Активные сессии периодически перепроверяют членство (предложение: раз в сутки). Так доступ закрывается и после выхода из организации.

## Альтернативы

- **Вход по magic link.** Знаком по ai-ticketbuyer, но требует почтовой инфраструктуры и не связан с членством в организации. Отклонено для внутреннего инструмента.
- **Корпоративный SSO (SAML или OIDC).** Лучше для больших компаний, для нас избыточно. Отложено.
- **Общий пароль.** Небезопасно и не отслеживается. Отклонено.

## Последствия

- Нужно зарегистрировать OAuth App в организации и положить секрет в переменные окружения.
- Внешние авторы без членства в организации в инструменте не работают. Для них нужен отдельный процесс, он вне v1.
