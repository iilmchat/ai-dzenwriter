# Roadmap DzenWriter

**Статус:** актуально на 2026-10-25, после закрытия E1–E11 и хвостов P0/P1.
MVP технически готов; впереди выход в прод — чек-лист запуска в
[07-operations](07-operations.md), юридические пункты ещё открыты.
**Формат:** направления и приоритеты, а не жёсткие даты. Что именно сделано и
как проверено — в [04-implementation-status](04-implementation-status.md);
очередь задач после MVP — [08-product-backlog](08-product-backlog.md).

## 1. Принципы

- **Нет факта — нет утверждения.** Проверки блокируют переход, а не советуют;
  ложные срабатывания подтверждает автор с комментарием.
- **Человек утверждает.** Генерация даёт черновик хранённого стиля, решение о
  ревью и публикации остаётся за людьми; автор не утверждает свой материал.
- **Правила как конфигурация.** Стили, форматы, списки проверок и базовый промпт
  лежат в git и меняются через PR, а не правкой кода.
- **Публикация в Дзен вручную** (ADR-0002): экспорт пакета и отметка ссылкой,
  автоматизации редактора нет.
- **Сначала закрываем риски, потом добавляем функции.** Юридические пункты,
  бэкапы и мониторинг важнее новых экранов.
- **Каждая пользовательская функция — с тестом и обновлением документации**
  в том же PR.

## 3. Ближайший горизонт

### P0 — выйти в прод

Техническая и юридическая части расписаны с владельцами в
[07-operations](07-operations.md), раздел 2. Здесь — суть.

- [ ] **Юридические пункты раздела 9 [06-legal-and-safety](06-legal-and-safety.md)**:
      обработка заметок опыта (согласия, ПДн), маркировка рекламы, условия
      провайдера LLM, сверка правил Дзена, маркировка ИИ-контента, реестр
      обработчиков. Закрыть у юриста — иначе запуск не разрешается.
- [ ] **Домен, TLS и внешний reverse proxy**; `WEB_ORIGIN` = публичный HTTPS-адрес.
- [ ] **OAuth App** (callback, организация) и `ADMIN_GITHUB_LOGINS` —
      первый администратор вошёл и получил роль.
- [ ] **Секреты**: `POSTGRES_PASSWORD` и `LLM_API_KEY` не из примеров, `.env`
      с правами 600; порт PostgreSQL закрыт firewall.
- [ ] **Настоящий провайдер LLM** вместо mock: ключ и модель проверены
      учебной генерацией; `LLM_PROVIDER=mock` в продакшене запрещён.
- [ ] **Лимиты генерации** по договору с провайдером (`LLM_DAILY_LIMIT_PER_USER`,
      `LLM_DAILY_BUDGET_USD`, цены токенов).
- [ ] **Бэкапы**: cron в 02:30 МСК (`scripts/backup-db.mjs`), внешнее копирование
      (rclone в S3-совместимое хранилище), учебная проверка восстановления
      (`pnpm db:backup:verify`) на стенде.
- [ ] **Очистка сессий**: cron в 03:00 МСК.
- [ ] **Мониторинг `/health` и `/ready`** с оповещением дежурного.
- [ ] **Срок хранения логов с IP** определён (решение за юристом).
- [ ] **CI зелёный на релизном коммите**, образы собраны и помечены версией;
      предыдущий образ доступен для отката.
- [ ] **Запись о запуске подписана** владельцем продукта и Tech lead
      ([07-operations](07-operations.md), раздел 2.3); проведена учебная генерация
      на реальном провайдере и проверка восстановления.

## 4. Средний горизонт

- **Аналитика генерации** (P2-7): дашборд запусков, стоимости и причин
  `needs_input`/`failed` по стилям и промптам — решать, где тратится бюджет.
- **Бриф и план статьи до генерации** (P2-1): тезисы и структура — меньше
  пустых генераций.
- **Локальные правки после генерации** (P2-2): перегенерация фрагмента,
  варианты заголовка.
- **Графики метрик** (P2-8): динамика по датам вместо таблицы снимков.
- **Уведомления** (P2-5): о возврате на доработку, назначении ревьюером и
  плановой дате.
- **Календарь публикаций** (P2-6): плановые даты и загрузка авторов.

## 5. Сознательно не входит

- **Автопубликация в Дзен** и автоматизация редактора (ADR-0002): только пакет
  и ручная публикация.
- **Многореплики и микросервисы**: один экземпляр API и один хост Docker
  Compose; масштабирование — только по доказанной необходимости.
- **RSS и сбор новостей, генерация изображений**: факты вносит человек,
  обложка — по `image_prompt` из пакета.
- **Мобильная версия, редактор стилей в интерфейсе**: стили правятся в git
  (ADR-0003).

Эти пункты не определяют архитектуру; возвращаться — только по итогам пилота.

## 6. Процесс выкладывания

1. Изменения попадают в `main` через PR или коммиты с проверками
   (`pnpm lint`, `pnpm typecheck`, `pnpm test`, e2e) и обновлёнными доками.
2. Перед обновлением прод — резервная копия (`pnpm db:backup`).
3. На хосте: `docker compose up -d --build --wait`; миграции применяет сервис
   `migrate`; откат миграций не автоматизирован, схема меняется только вперёд.
4. Проверка после выкладывания: `/health`, `/ready`, вход, доска, одна
   учебная генерация.
5. При ошибке — вернуть предыдущий коммит и образ, снова проверить здоровье;
   зафиксировать инцидент в журнале [07-operations](07-operations.md).

## 7. Definition of Done для функции

- Поведение описано в профильном документе (`04-implementation-status` или
  `08-product-backlog`) и, если менялся сценарий, в дизайне.
- Правила и гейты покрыты тестами: примеры «должен падать» и «должен внутри».
- Изменения схемы — миграция без правки старых файлов.
- Правка стиля или промпта — через PR с валидацией конфигурации.
- Элементы интерфейса проверены клавиатурой и axe без критичных нарушений.
- Пройдены `pnpm format:check`, `lint`, `typecheck`, `build`, `config:validate`,
  `test` и e2e.
