## Решения, принятые в E1

- Миграции — отдельный сервис `migrate` в compose и отдельный шаг CI. Это отличие от ai-ticketbuyer, где API мигрирует при старте.
- Порты на хосте задаются переменными `POSTGRES_PORT` и `WEB_PORT`. На машине разработки 5432 и 8080 заняты другими проектами.
- `@dzenwriter/shared` собирается tsup в ESM и CJS: веб (Vite) и API (NestJS, CJS) используют разные системы модулей.
- Тесты NestJS идут через SWC (`unplugin-swc`): esbuild не поддерживает `emitDecoratorMetadata`.
- Интеграционные тесты БД работают в транзакциях с откатом и не оставляют данных.
- Dev-режим API запускается через Nest CLI (`nest start --watch --tsc`). `tsx` на esbuild не выдаёт метаданные декораторов, и внедрение зависимостей ломается: `/ready` отдавал 500. Проверено на dev-сервере.
- Порты задаются в корневом `.env`: `API_PORT`, `WEB_DEV_PORT`, `WEB_PREVIEW_PORT`, `POSTGRES_PORT`, `WEB_PORT`. Dev-сервер веба, предпросмотр, Playwright и API читают одни и те же значения.
- Корневой `.env` веб-конфиг читает через `util.parseEnv` без побочных эффектов. `loadEnv` из Vite пишет переменные в `process.env`, и `NODE_ENV=development` из `.env` выбирал development-JSX в production-сборке (`jsxDEV is not a function` в браузере). Режим сборки задаётся самим Vite, без переопределений.
- Миграции в CI идут до тестов: тесты API работают с таблицами, а база в CI пустая.

## Решения, принятые в E2

- Токен доступа GitHub используется один раз в запросе входа и нигде не сохраняется. Нужны только `read:user` и `read:org`.
- Членство в `iilmchat` проверяется при каждом входе. Пользователь вне организации получает отказ с причиной, а в аудит пишется запись без персональных данных.
- Первый администратор: логин из `ADMIN_GITHUB_LOGINS` получает роль `admin`, пока в системе нет ни одного администратора. Дальше роли меняет администратор.
- Callback OAuth идёт через origin приложения (`WEB_ORIGIN` + `/api/v1/auth/github/callback`). Cookie одного origin с SPA, в dev и compose запрос идёт через прокси.
- CSRF: state лежит в HttpOnly cookie 10 минут и сверяется в callback. Для изменяющих запросов Origin должен совпадать с `WEB_ORIGIN` или отсутствовать. Поверх этого работает SameSite=Lax.
- Охранник глобальный: по умолчанию нужен вход, открыты только `@Public()` маршруты (`/health`, `/ready`, вход и выход). Роли задаются `@Roles()`.
- В логах не попадает строка запроса: в ней одноразовый `code` и `state` OAuth. Логируется только путь.
- Аудит: вход, отказ, выход, смена роли, отключение и включение пишутся в `audit_log`. В payload только ID и значения ролей, без логинов и имён.
- Без OAuth-секретов сервис запускается, а вход отвечает сообщением «не настроен». Так работают CI, e2e и локальная разработка без OAuth App.
- Маршрутизация (React Router) пока не подключена: экран один. Router добавим в E3 вместе с доской.

## Что не сделано (сознательно)

- Периодическая перепроверка членства раз в сутки (ADR-0005). Сейчас членство проверяется при входе, а сессия живёт 30 дней. Для фоновой проверки нужен серверный токен организации или GitHub App: решение открыто.
- Экран управления пользователями в интерфейсе. API для ролей и отключения есть, UI будет вместе с E3 или отдельной задачей.
- Очистка истёкших и отозванных сессий. Относится к эксплуатации (E11).
- Переименование логина на GitHub. Если новый логин занят другим пользователем в системе, вход вернёт ошибку 500. Случай редкий, решается вручную.
- Шрифты Inter и Manrope грузятся из Google Fonts (`apps/web/index.html`). Для продакшена нужны локальные `.woff2` (см. `FONTS.md` в ai-brand).
- Образ `api` ставит pnpm через `npm install -g`, на медленной сети это долго. Оптимизация: corepack или кэш слоя.
- Движок проверок (E7) ещё не реализован. Ключи `checks` валидируются по списку `STYLE_CHECK_IDS` из `packages/shared`.
- Юридические пункты из [06-legal-and-safety](06-legal-and-safety.md) не закрыты, в том числе срок хранения логов с IP.
- Официальные способы публикации в Дзен не проверены (ADR-0002).

## Что проверено

- `pnpm lint`, `pnpm typecheck`, `pnpm format:check`, `pnpm config:validate`, `pnpm build` проходят без ошибок.
- `pnpm test`: shared 5, db 6, api 54, web 5 тестов, всего 70. Все проходят на PostgreSQL 16.
- `pnpm test:e2e`: 2 сценария в Chromium. Главная показывает состояние сервиса и кнопку входа. Вход без настроенного GitHub показывает понятное сообщение.
- `pnpm dev`: API на 4010 отвечает `/health` и `/ready` (200), веб на 5183 отдаёт приложение, а его прокси `/ready` возвращает 200.
- `docker compose up -d --build --wait`: postgres здоров, migrate завершается с кодом 0, api и web здоровы. Через nginx: `/` отдаёт приложение, `/ready` отвечает 200, `/api/v1/me` без входа отдаёт 401 в формате problem+json. Вход без секретов GitHub возвращает на главную с `error=unavailable`, выход с чужим Origin получает 403. В логах callback нет строки запроса с кодом OAuth.
- Бренд-ассеты совпадают с `ai-brand` по коммиту `e143a2bb894ec532f0afcdf9c5e4d48d83612405`.
