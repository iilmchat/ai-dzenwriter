# Право, персональные данные и безопасность

**Статус:** черновик v0.1, требует юридической проверки до запуска  
**Дата:** 22.10.2026

> Этот документ — проектные ограничения и чек-лист, а не юридическая консультация. Перед запуском каждый пункт проходит проверку юристом либо отклоняется с решением владельца.

---

## 1. Доступ и учётные записи

- Вход только через GitHub OAuth. Членство в организации `iilmchat` проверяется при каждом входе (ADR-0005).
- Роли: author, reviewer, admin. Изменение роли пишется в аудит.
- Сессии: HttpOnly, Secure, SameSite=Lax. TTL 30 дней. Выход и отключение пользователя отзывают сессии.
- Защита от CSRF: для всех изменяющих запросов проверяется заголовок `Origin`, дополнительно работает SameSite cookie.
- Ограничение частоты: вход, генерация (на пользователя), экспорт.

## 2. Персональные данные в опыте

Опыт конкретного человека, скорее всего, содержит персональные данные по смыслу 152-ФЗ «О персональных данных». Это предварительная оценка, её подтверждает юрист.

| Требование                                 | Как обеспечиваем                                                                                            | Статус           |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------- | ---------------- |
| Согласие на обработку и публикацию истории | Отметка `consent_confirmed` с датой и подтверждающим ревьюером; без согласия факт не одобряется             | Реализовать в E4 |
| Обезличивание                              | Имена людей и компаний заменяются ролями до сборки промпта; проверка `personal_names_forbidden`             | Реализовать в E7 |
| Минимизация                                | В промпт попадает только текст заметки, без контактов и служебных полей                                     | Реализовать в E6 |
| Право на отзыв                             | Отзыв удаляет текст заметки и помечает связанные версии как «источник отозван». В аудите остаются ID и дата | Реализовать в E4 |
| Срок хранения                              | Заметки — до отзыва или 2 года (предложение)                                                                | Утвердить        |
| Место обработки данных                     | Уточнить у провайдера LLM                                                                                   | Открыто          |

Обезличивание — не то же самое, что анонимизация. Юрист оценивает, достаточно ли убрать имена и детали, чтобы человека нельзя было узнать.

## 3. Реклама и маркировка

- Материалы о собственных продуктах и партнёрах могут считаться рекламой по ФЗ «О рекламе». Тогда нужна маркировка и, если применимо, идентификатор ОРД. Точный состав обязательных реквизитов определяет юрист.
- В DzenWriter это реализуется так: поле `advertising_label` в версии; гейт `ad_disclosure_required` блокирует переход в `approved`, если продукт упомянут без маркировки.
- Решение о маркировке принимает ответственный за материал, а не модель. Модель только предлагает (`advertising_label_suggested`).
- Личный опыт, в котором упомянут продукт, по умолчанию считается рекламным, пока юрист не решит иначе.

## 4. Авторское право и цитирование

- Цитаты из новостей короткие, в кавычках, с именем автора и источника. Остальное — пересказ своими словами.
- URL первоисточника сохраняется в факте (`source_url`), даже если в тексте ссылки нет. Это нужно для проверки.
- В v1 приложение не копирует страницы и не парсит сайты. Автор вставляет текст цитаты вручную.
- Для обложек `image_prompt` не запрашивает узнаваемые лица реальных людей и логотипы сторонних компаний. Если обложка нужна, её создаёт или выбирает человек, у которого есть права на использование.

## 5. Чувствительные темы и дисклеймеры

- Медицина, право и финансы: модель помечает тему (`disclaimer_needed`), а гейт `disclaimer_required` требует текст дисклеймера из конфигурации стиля.
- Утверждения о лечении, юридической силе и инвестиционной доходности без источника не допускаются.
- Дисклеймер не заменяет проверку. Для тем с высокой ценой ошибки материал проверяет специалист.

## 6. Провайдер LLM и обработка данных

- Проверить до запуска: условия обработки данных, отсутствие обучения на наших данных, регион обработки, срок хранения логов у провайдера.
- Провайдеру передаётся только необходимое для генерации: тема, стиль, факты с метками и обезличенные заметки.
- Ключи API хранятся только в переменных окружения сервера и не попадают в браузер.
- По каждому провайдеру ведётся запись в реестре обработчиков данных (внутренний документ).

## 7. Правила платформы Дзена

Перед публикацией автор проходит чек-лист. Он входит в пакет экспорта.

- Заголовок соответствует содержанию, без ложных обещаний.
- Текст самодостаточен: внешние ссылки не нужны для понимания.
- Маркировка рекламы и партнёрских материалов поставлена, если нужна.
- Источники и даты указаны.
- Дисклеймер есть, если тема чувствительная.
- Обложка не нарушает права на изображения.

Правила Дзена меняются. Перед запуском и далее раз в квартал ответственный сверяет чек-лист с актуальной справкой платформы. Требования к маркировке ИИ-контента проверяются там же.

## 8. Безопасность приложения

- OWASP ASVS — ориентир. Риски OWASP Top 10 проверяются в ревью PR.
- Ответ модели считается недоверенным вводом. Markdown рендерится с санитизацией, сырой HTML не выполняется, ссылки открываются с `rel="noopener noreferrer"`.
- Prompt injection: факты помечаются как данные, инструкции внутри фактов игнорируются, ответ проходит проверку схемы и гейты.
- Секреты только в переменных окружения. `.env` в `.gitignore`. В репозитории — `.env.example` без значений.
- Зависимости: Dependabot, `pnpm audit` в CI, фиксированные версии в lock-файле.
- В логах нет текстов статей, фактов, промптов и персональных данных. Ошибки пишутся с `requestId`.
- В логах запросов есть IP-адрес клиента (`x-forwarded-for`), а это персональные данные. Срок хранения логов — вопрос к юристу и эксплуатации (предложение: 30 дней).
- Резервные копии ежедневно. Восстановление проверяется раз в месяц.
