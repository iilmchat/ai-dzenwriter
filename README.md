Внутренний инструмент IIRuChating для планирования, генерации, проверки и отслеживания статей для Яндекс Дзен.

**Статус:** E1–E11 выполнены в технической части: монорепозиторий, база, API, веб, Docker, CI, вход через GitHub, роли, доска материалов, переходы по статусам, факт-база, привязка фактов к материалам, справочник продуктов, генерация с mock LLM, движок проверок, редактор с версиями, пакет для Дзена, метрики (ручной ввод и импорт CSV), резервные копии с проверкой восстановления и runbook сбоев LLM. После E11 добавлены read-only ревью текста, главный E2E-сценарий до публикации, показатели пилота с оценкой редактора, экран «Мои задачи», доска с блокировками и перемещением карточек, автосохранение и диалог конфликта версий в редакторе, экран журнала аудита для администратора. Юридические пункты перед запуском отработаны юристом 25.10.2026, замечаний нет. Подробнее — [docs/04-implementation-status.md](docs/04-implementation-status.md) и [docs/07-operations.md](docs/07-operations.md).

**Фокус v1:** ИИ — агенты, LLM-системы и их внедрение, новости индустрии, продукты и опыт IIRuChating.

## Что будет уметь

- Редакционный план: доска от идеи до публикации.
- Факт-база: цитаты источников с датами, подтверждённые факты о компании и продуктах, согласия на личный опыт.
- Четыре стиля, настраиваемых в git: новости индустрии, наш опыт, описание продуктов, личный опыт.
- Генерация по стилю и формату с проверками: числа, имена и утверждения сверяются с фактами.
- Редактор с предпросмотром в духе Дзена, версии и сравнение.
- Ревью, при котором автор не утверждает свой материал. Пакет для Дзена и отметка публикации.
- Отслеживание публикаций: метрики вручную или CSV-импортом, сравнение материалов.

## Принципы

1. Нет факта — нет утверждения. Проверки блокируют, а не советуют.
2. Человек утверждает. Генерация даёт черновик, публикацию делает человек после ревью.
3. Стили и правила — конфигурация в репозитории; изменения проходят через PR.
4. Каждая версия хранит вход, версию стиля, промпт, модель и результаты проверок.
5. Публикация в Дзен — вручную (ADR-0002). Автоматизацию редактора не делаем.
6. Интерфейс — в брендовом стиле IIRuChating (ai-brand), доступность по WCAG 2.2 AA.

## Быстрый старт

Нужны Node.js 24, pnpm 12.11.2 и Docker Desktop.

```bash
corepack enable            # или: npm install -g pnpm@12.11.2
pnpm install
cp .env.example .env       # в Windows: copy .env.example .env
pnpm db:up                 # PostgreSQL в Docker
pnpm db:migrate            # схема и миграции
pnpm db:seed               # демо-данные, только для разработки
pnpm dev                   # API на http://localhost:4000, веб на http://localhost:5173
```

Откройте http://localhost:5173: страница покажет состояние сервиса. Порты по умолчанию: API 4000, веб в разработке 5173, предпросмотр 4173, PostgreSQL 5432, compose-веб 8080. Если порт занят, задайте свой в `.env` (`API_PORT`, `WEB_DEV_PORT`, `WEB_PREVIEW_PORT`, `POSTGRES_PORT`, `WEB_PORT`).

### Полный стек в Docker

```bash
docker compose up -d --build --wait
```

Откройте http://localhost:8080 (порт задаётся переменной `WEB_PORT`). Миграции выполняет отдельный сервис `migrate`.

Остановить: `docker compose down`. Полный сброс вместе с данными: `docker compose down --volumes`.

### Вход через GitHub

Вход работает после регистрации OAuth App в организации `iilmchat` (Developer settings → OAuth Apps → New OAuth App):

- **Homepage URL:** адрес приложения, он же `WEB_ORIGIN`, например `http://localhost:5173`.
- **Authorization callback URL:** `WEB_ORIGIN` и путь `/api/v1/auth/github/callback`, например `http://localhost:5173/api/v1/auth/github/callback`.

Client ID и Client secret запишите в `.env` как `GITHUB_CLIENT_ID` и `GITHUB_CLIENT_SECRET`. В `ADMIN_GITHUB_LOGINS` укажите свой логин GitHub: он станет первым администратором. Без секретов сервис работает, а вход показывает понятное сообщение.

Открывайте приложение по адресу из `WEB_ORIGIN` (например, `localhost`, а не `127.0.0.1`). Изменяющие запросы с другого источника отклоняются, и выход в этом случае не сработает.

## Разделы интерфейса

- `/` — доска материалов по статусам с фильтрами по стилю, владельцу и блокировкам. Карточка показывает следующее действие, блокирующие проверки и перемещается между колонками мышью или через меню с клавиатуры.
- `/tasks` — «Мои задачи»: материалы, где вы автор или ревьюер, сгруппированные по следующему действию.
- `/articles/:id` — карточка: условия стиля, переходы, версии, решения ревьюера, публикации, правка параметров, панель генерации со стадиями и добавлением факта из вопросов модели, панель проверок с подтверждением.
- `/articles/:id/edit` — редактор: исходник Markdown, предпросмотр в духе Дзена, панель проверок, метаданные, утверждения, история версий и сравнение; локальное автосохранение и диалог конфликта версий.
- `/facts` — факт-база: библиотека фактов, создание, одобрение ревьюером, исправление одобренного факта, согласие на личный опыт и его отзыв. Фильтры по типу, статусу и тексту.
- `/products` — справочник продуктов. Читают все, меняет администратор; продукт архивируют, а не удаляют.
- `/publications` — публикации: что готово к публикации, что запланировано, что уже вышло. Отсюда скачивают пакет для Дзена и вносят ссылку на статью.
- `/metrics` — метрики публикаций: просмотры, прочтения, время чтения, ручной ввод и CSV.
- `/styles` — стили и форматы из `config/`, только чтение.
- `/admin/pilot` — показатели пилота: время до утверждения, возвраты, гейты, правки после генерации, оценка редактора, запуски и стоимость; только для администратора.
- `/admin/users` — роли и отключение пользователей, только для администратора.

Демо-материалы появляются после `pnpm db:seed`. Все материалы относятся к разным статусам, так что доска сразу показывает колонки.

## Переменные окружения

Все переменные описаны в [`.env.example`](.env.example). Файл `.env` не коммитится, секреты в репозиторий не кладём. Вход через GitHub использует `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `GITHUB_ORG` и `ADMIN_GITHUB_LOGINS`.

Генерация работает на заглушке `LLM_PROVIDER=mock`: она отвечает корректным JSON и годится для разработки и CI. Для настоящей модели укажите `LLM_PROVIDER=openai`, `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL`. Лимиты задаются `LLM_DAILY_LIMIT_PER_USER` и `LLM_DAILY_BUDGET_USD`, стоимость считается по ценам `LLM_INPUT_PRICE_PER_MTOK` и `LLM_OUTPUT_PRICE_PER_MTOK`. Защита API: `RATE_LIMIT_MAX` (по умолчанию 300 запросов в минуту на IP) и `AUTH_RATE_LIMIT_MAX` (30 в минуту на вход через GitHub), ответ при превышении — 429 в problem+json; CSP сайта задаётся конфигом nginx `docker/nginx/default.conf`.

Переменные проверяются при старте. Если значение неверно, API не запускается и называет переменную в сообщении.

## Структура

```text
apps/
  api/           NestJS API: конфигурация, здоровье, вход, роли, ошибки, логи
  web/           React и Vite: вход и страница состояния сервиса
packages/
  db/            схема Drizzle, миграции, демо-данные
  shared/        константы, Zod-схемы конфигурации и контракты API
config/          форматы, стили и правила проверок: YAML, проверяются при старте
prompts/         базовый промпт Dzen Writer
design/brand/    ассеты ai-brand (закреплённый коммит)
docker/          конфигурация nginx для образа web
e2e/             сквозные тесты Playwright
docs/            дизайн, данные, backlog, статус, UI, право, эксплуатация, ADR
scripts/         резервные копии PostgreSQL и проверка восстановления
prototype/       кликабельный HTML-прототип интерфейса
.github/         CI и Dependabot
```
